# 技术债与路线图备忘：分 P 视频处理

> 来源自 `apps/mobile/docs/TECHNICAL_DEBT.md`

## 🐛 已知问题：分 P 视频处理

**目前 Bilibili API 的限制导致无法在导入阶段完美解决去重问题。**

### 问题描述

B 站视频唯一可播放单位是 `(bvid, cid)`，但在本项目中存在两种入口：

1. **整视频入口** (`isMultiPage = false`): 无 `cid`，默认播放第一 P。
2. **分 P 入口** (`isMultiPage = true`): 已知 `cid`。

这导致同一个视频的第一 P 可能对应数据库中的两条记录，且无法简单去重。

### 困难点

1. **可靠性**: 分 P 顺序不可靠，UP 主可能后续增删或重新排序分 P。
2. **性能与风控**: 批量获取 `cid`（即对歌单每个视频调用 `/x/player/pagelist`）成本过高，极易触发 B 站高频访问风控验证码（412 / 封禁 IP），导致导入歌单时无法预先获取全部 `cid` 进行去重。

### 暂行方案与桌面端演进

1. **按需懒加载 (Lazy Evaluation)**：
   - 导入歌单或搜索时只存 `bvid`；
   - 只有在真正点击播放该 Track 时，才在 `playTrackHelper.ts` 中发起 `pagelist` 请求探知是否包含多分 P；
2. **播放队列就地替换 (In-place Replacement)**：
   - 在 `VideoPartsModal` 切换分 P 时，若当前播放的是同一视频，直接就地更新当前播放队列的条目，避免用户反复点切造成播放队列爆炸；
3. **支持全量展开**：
   - 在弹窗中提供“播放全部分 P”与“追加全部”，由用户主动触发将该稿件的所有分 P 一键展开入队。
