本会话作为项目总会话（Master / Orchestration Hub），在敏捷迭代与 MVP 维护中具有不可替代的**“总调度与总装中心”**作用。

如果把各个独立的新会话比作**“专门的零件加工车间”（只负责把某一个功能改好、测试好），那么本会话就是“整车总装与出厂质检中心”**，核心承担以下 4 大关键职责：


1.  最终版本发布与总装打包（Release Center）
子会话不做耗时打包：为了开发效率，子会话里只进行 2~5 秒的局部语法检查（pnpm build / cargo check）。
总会话负责全量出厂：当你在各个新会话中分别完成了若干功能并合并到 dev 后，回到本会话执行：
更新全局版本号（如升级为 v1.1.4）；
更新 README.md 与更新日志（Changelog）；
将 dev 正式合并到 main 并打上 Release Tag；
运行完整的 MSVC 编译，生成最终的安装包、便携版和 ZIP（apps/desktop/src-tauri/target/release）。


2.  架构演进与全局规范治理（Governance）
维护和扩充项目的全局规则（如刚刚编写的 docs/ISOLATION_DEV_GUIDE.md）；
涉及跨模块的重大基础设施变动（例如升级 Tauri 2.0 依赖、升级 Node/Rust 工具链、重构全局 SQLite 数据库架构）；
当系统新增了业务大模块时，在总会话中为全局功能映射表扩充新条目。


3.  跨模块联调与疑难杂症排查（Cross-Module Debugging）
某些深层 Bug 往往不是单一文件的代码问题，而是跨越了 “前端 UI ➔ Zustand 状态 ➔ Web Audio 播放引擎 ➔ 本地 Rust 流代理 ➔ B 站 WBI 鉴权” 的整条长链路。
单功能子会话视野受限，而总会话拥有完整的全景架构上下文，最适合用于定位跨窗口不同步、内存泄漏、网络反爬死锁等全局性疑难杂症。


4.  分支总览与全库灾备救援（Disaster Recovery）
统筹查看全局分支网络（main、dev 及各特性分支）；
当某个子会话操作失误、误删了分支或遭遇复杂的 Git 合并冲突时，总会话可以作为“全局上帝视角”进行仲裁、代码回溯和无损救援（包括随时调取我们已备份的 Bili_Player_full_backup.bundle）。
推荐的日常最佳协作模式
日常改需求 / 修具体 Bug ➔ 开新会话（告知阅读指南 + 指定功能，极速干净）；
发新版本 / 大版本发布 / 架构统筹 ➔ 回到本会话（一键完成合并、质检与 Release 打包）。
